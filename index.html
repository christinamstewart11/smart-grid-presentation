Why this matters

A cyberattack can switch off the lights for a whole city

In December 2015, attackers broke into the computer systems of three electricity distribution companies in Ukraine. Using the operators' own control software, they opened circuit breakers remotely.

Customers left without power225,000
Distribution companies hit3

It was the first publicly confirmed cyberattack to cause a power outage. Jamaica's grid is adding smart meters and remote switching, so the same kind of exposure is arriving here.

The core problem

  • Grid devices trust every message. Most industrial protocols have no password or signature, so a forged "open breaker" looks real.
  • Old defences only know old attacks. They match a list of known patterns and miss anything new.
  • An alarm alone doesn't help. Someone still has to understand it and act, fast and safely.

Key term 1

What is a power grid?

The grid is the network that carries electricity from where it is made to where it is used. Power flows one way, from big power stations out to customers.

GenerationPower stations make electricity.
TransmissionHigh-voltage lines carry it long distances with low loss.
SubstationSteps the voltage down and splits it into feeders.
DistributionLocal lines and breakers bring it to homes and businesses. My project models this part.

Key term 2

Grid vs smart grid

A smart grid is the same grid with a communication network added. Sensors, meters and controllers talk to a control room, so information flows both ways and the grid can be watched and switched remotely.

Key terms 3

The equipment, in plain words

PLC

Programmable logic controller

A rugged industrial computer that switches equipment on and off by following a program. In my project it opens and closes the breakers.

SCADA

Supervisory control and data acquisition

The control-room system that collects readings from the field and sends commands back to controllers like PLCs.

Relay / breaker

An electrically operated switch

A small current in its coil closes contacts that carry the mains power. Here, four relays act as the grid's breakers.

IoT node

Internet of Things sensor

A small wireless computer with sensors. My three nodes are smart meters that measure voltage, current and power.

Protocol

The language devices speak

Rules for how messages are formatted. EtherNet/IP (PLC) and MQTT (sensors) are used here. Most have no built-in security.

Gateway

The network's watchtower

A computer that every message passes through. Mine is a Raspberry Pi 5 that runs the AI and the operator screen.

Key terms 4

Seven kinds of attack the system must recognise

A1 · Denial of service

Floods the network with junk so real messages can't get through.

Like jamming a phone line.
A2 · Reconnaissance

Scans the network to find devices and weak points before attacking.

Like checking which doors are unlocked.
A3 · Unauthorised command

Sends a fake "open breaker" command to the PLC.

Like a forged order from the boss.
A4 · False data injection

Sends fake meter readings so operators or the AI act on lies.

Like a broken fuel gauge that reads full.
A5 · Replay

Records real messages and sends them again later.

Like replaying an old voicemail as new.
A6 · Man-in-the-middle

Secretly sits between two devices and reads or changes messages.

Like someone opening your post.
A7 · Messaging abuse

An unknown device joins the sensor message system to listen or publish.

Like a stranger in the group chat.
Rule for every test

All attacks are scripted and run only on my own isolated testbed, with no internet connection, as Jamaica's Cybercrimes Act requires.

Key terms 5

How can a computer tell that it's under attack?

An intrusion detection system (IDS) watches network traffic and readings and raises an alarm when something looks wrong. There are three main approaches, and my project combines them.

Signature-based

Match a list of known attacks

Works like antivirus. Few false alarms, but it cannot see anything new. Used here only as the baseline to beat.

Machine learning

Learn from labelled examples

The model is trained on thousands of one-second windows labelled "normal" or with the attack type, then names the attack it sees.

Anomaly detection

Learn what normal looks like

Flags anything unusual, even an attack nobody has seen before (a "zero-day"), at the cost of more false alarms.

Explainable AI

Operators won't trust a black box. Every alert in my system will list the top three reasons, for example "Node 2 reads 0.00 A while relay K2 is closed". A method called SHAP measures how much each input pushed the decision.

The gap

Nobody has put all the pieces together on real hardware

G1 · No realistic testbedNo study combines a real PLC, wireless sensors and real AC loads.
G2 · New attacks rarely testedModels are tested on the same attacks they were trained on.
G3 · No plain-language reasonsNo alert explains itself in terms an operator can check.
G4 · Detection without safe responseResponse is rare, simulated, and has no operator or safeguards.
G5 · No low-cost hardware resultsNo one measures speed on a small computer like a Raspberry Pi.

My project fills all five

  • A real testbed: industrial PLC, 3 wireless meter nodes, 3 real 120 V loads.
  • Unseen-attack tests: train without one attack type, then see if it is still caught.
  • Every alert explained in plain words on a touchscreen.
  • Tiered response with operator approval and a PLC safety lock.
  • Speed measured on the Raspberry Pi 5 itself.

Conceptual design

The testbed at a glance

1 · PowerMains passes through glass-box relays (the breakers) to three bulbs. Each bulb stands for a group of customers.
2 · ControlThe PLC opens and closes the relays, just like a utility switching a feeder.
3 · SensingThree smart-meter nodes measure each branch and report over Wi-Fi every second.
4 · AI gatewayThe Raspberry Pi 5 sees every message, detects attacks, explains them and responds.
5 · Attack and responseA scripted attacker laptop tries to break in. The gateway blocks it, and the operator approves any power switching.

Planned software · how the system responds

The more certain the AI is, the stronger the response

Every second, the gateway checks traffic, readings and relay states and gives a confidence from 0 to 100 % that an attack is happening. The software is designed; coding starts as the testbed is built.

Tier 0PLC safety lock, always on. The PLC only obeys commands carrying a valid code from the gateway, never switches too fast, and can lock everything off until a person presses Reset.always
Tier 1Log and alert with the top three reasons.≥ 50 %
Tier 2Rate-limit or ignore the suspect data or device.≥ 70 %
Tier 3Block the attacker at the firewall. Blocks expire after 5 minutes, and core devices can never be blocked.≥ 90 %
Tier 4Propose a safe state (switching power). It only happens if the operator approves on the touchscreen.operator

Standards, laws and ethics

Built to recognised rules

IEC 62443

Industrial cybersecurity. The testbed is split into zones; the PLC only talks to the gateway.

NIST SP 800-82

Operational technology security. Monitoring and staged incident response shape the gateway.

IEEE 1686

Device cybersecurity. Every command, alert and operator action is logged.

IEC 61131-3

PLC programming. The PLC program is written in ladder diagram.

IEC 60204-1

Machine electrical safety. The emergency stop removes power from all relay coils.

IPC-2221

PCB design. Wide spacing between 120 V and low-voltage areas on the node PCB.

IEC 60529

IP rating. The electronics sit in an IP67 box with sealed cable glands.

Jamaican law

Cybercrimes Act 2015, Data Protection Act 2020 and Electricity Act 2015: own equipment only, no personal data, wiring checked before use.
